# Independent cash collection release — terminal 2 to terminal 1

This branch starts at integrated `b243aac` and contains only non-card request serialization, tests and isolated rehearsals. It can be merged and deployed independently of hosted physical EMV and check-detail decisions. The existing digital checkout, standalone card checkout, and continuous Payper configuration are unchanged. No new database migration is required; the non-card order/POS schema was already applied in production.

The deployed `payper-noncard-collection` Edge function accepts one actual cash payment for an existing scheduled order or standalone POS sale. For a scheduled cashier collection it recalculates and locks the full outstanding balance, validates billing and VAT from frozen server facts, blocks an existing document requiring review, creates one payment and sale, then performs one `CreatePayperInvoice` request. The September 2026 Services REST manual printed pages 13 and 32–33 specify empty `trxRecordId`/`Uid`, `typeDocument="Invoice-Receipt"`, `Cash` receipt line, actual payment date and amount in agorot, and VAT-inclusive invoice lines. The corrected serializer follows that contract. An ambiguous issuance response stays in reconciliation; it is never replayed. `send_by_mail=true` requests delivery, but receipt must be checked independently.

Terminal 1 should integrate this branch and deploy the revised `payper-noncard-collection` Edge function with its existing verified provider credentials.
