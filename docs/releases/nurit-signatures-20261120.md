# Order signatures: separate release candidate — 2026-11-20

This branch starts at protected Production application SHA `e29fedd5b0270704dbe93b9e5fae7f81477ce631`. It imports only the restored order-signature UI, Vercel PDF API and its dependencies, private-PDF renderer, restored `send-order-signature` source, tests and related Vercel function configuration. It does not import older Orders/Schedule/financial application files or alter the current payment backend, chatbot webhook or provider settings. No schema migration is proposed here: the previously audited live database contains the signature RPCs and private bucket, but those conditions must be checked again before release.

The server creates a frozen order-confirmation revision, stores the unsigned PDF in `order-signatures-private`, hashes it, issues an opaque expiring signing URL, validates bounded signature strokes, and stores the signed version under a deterministic private key. Staff PDF reads verify stored hashes. Public token reads are limited to the associated revision. The recipient for email delivery is validated on the server and the delivery RPC claims an attempt before provider contact. Unknown provider outcomes stay uncertain; a repeat requires an explicit manual-resend decision. The historical PDF download and existing order UI remain present. The old PDF toolbar email button now opens this versioned delivery panel and passes its edited recipient; it no longer calls the incompatible legacy `send-order-doc` payload. The existing direct WhatsApp toolbar action remains available and is outside this versioned email acceptance path.
