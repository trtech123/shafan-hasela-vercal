## סדר פריסה לאחר אישור נפרד

1. החל רק את `202611240001_order_signature_browser_response.sql`. אמת טבלה ריקה, RLS פעיל, `authenticated` ללא INSERT/UPDATE/DELETE וללא EXECUTE על `record_order_signature_response`, ו־`service_role` עם EXECUTE. אמת שמספרי הזמנות, לקוחות, לידים וגרסאות חתימה לא השתנו.
2. פרוס רק את `send-order-signature` עם שינוי המייל. בדוק ב־Edge בקשה `POST {}` עם JWT של עובד מורשה ו־`apikey` הציבורי: התוצאה הצפויה היא `400 invalid_request`, משום שהאימות עבר אך הגוף אינו תקין. ללא JWT התוצאה הצפויה היא 401. אין לכלול מזהה גרסה, נמען או קישור בבדיקה; אין לגעת בספק או ליצור רשומת משלוח. אם מתקבל 401 עם JWT תקף, עצור לפני פריסת הממשק וחקור את נתיב האימות.
3. פרוס את קומיט המועמד המדויק ל־Vercel Production. אמת שה־alias החי מצביע למזהה הפריסה החדש ושקוד המקור שלו כולל את קומיט הייצור הקודם ואת תיקוני הגבייה והלידים.
4. באמצעות חשבון עובד מורשה, בדוק ללא יצירת הזמנה/מסמך אמיתיים: היסטוריית אישורים קיימת, כפתור מייל מרכזי עם קישור לטופס, מסלול PDF תחת גילוי ואישור, טעינת הטופס בדפדפן, וקריאות קריאה בלבד להצגת פרטי חתימה בהזמנה, בלקוח ובליד. בדוק מסכי קופה, תשלומים, חשבוניות, לקוחות ולידים. אין להפעיל `deliver` עם נמען אמיתי בשלב זה.
