# מסירה למנהלת דף Base44 — לידים של יום גיבוש

עמוד `https://www.shafan-hasela.com/he/team-building-day/` מטמיע את `https://vegan-climb-the-summit.base44.app/`. בדף Base44 מופיע אותו טופס בראש העמוד ובתחתיתו. יש לחבר **פעם אחת את מנגנון השליחה המשותף**, כדי ששליחה מכל מיקום תעבור באותו מסלול. לא לשלוח פנייה אמיתית לצורך בדיקה ללא תיאום.

## מה לשנות ב־Base44

1. בדקי בקוד Base44 האם שני המופעים מרנדרים את אותו רכיב ומשתמשים באותה פעולת `submit`. בדקי אם הפעולה רק פותחת WhatsApp, ואם קיימת כבר שמירה ל־Base44 או שליחה ליעד אחר. אם הפעולה משותפת, חברי אליה את הקליטה **פעם אחת בלבד**; אל תוסיפי קריאה נוספת בכל מיקום שמרנדר את הרכיב. אם כיום יש שתי פעולות נפרדות, רכזי אותן תחילה בפעולת שליחה משותפת אחת. דווחי לנו על כל שמירה קיימת כדי למנוע כפילות.
2. בפעולת השליחה המשותפת, לאחר לחיצה מפורשת, בצעי ולידציה לשם ולטלפון, ושילחי את הפרטים אל **פונקציית שרת אחת של Base44**. השדות בטופס הנוכחי הם שם, טלפון, נושא והודעה אופציונלית; אין בו אימייל. יש לייצר `submissionId` מסוג UUID פעם אחת לכל פנייה ולהשתמש באותו מזהה גם בניסיון חוזר. יש להפעיל הגנת ספאם בצד השרת.
3. פונקציית השרת תשלח POST ב־JSON אל `landing-lead-webhook` של Supabase. היא תעביר `formId: "nurit-team-building"`, את `submissionId`, `submittedAt` בתקן ISO, `pageUrl: "https://vegan-climb-the-summit.base44.app/"`, את `fields.name`, `fields.phone`, את `topic` ואת `inquiry` אם נמסרה. אפשר לצרף `fields.email`, קמפיין ו־UTM רק אם נאספו בפועל. כתובת ה־endpoint המדויקת תימסר בערוץ תפעולי בעת ההפעלה.
4. האימות מתבצע **בשרת בלבד**: צרי גוף JSON מדויק (`rawBody`), זמן Unix בשניות (`timestamp`), וכותרות `X-Landing-Timestamp: <timestamp>` ו־`X-Landing-Signature: sha256=<hex HMAC-SHA256(secret, timestamp + "." + rawBody)>`. הסוד יוגדר רק ב־Base44 server secrets וב־Supabase Edge secrets. אין להכניס אותו לקוד הדפדפן, ל־HTML, לכתובת URL או ללוגים. כל ניסיון חוזר ישתמש באותו `submissionId`, עם חתימה מחושבת מחדש לפי גוף הבקשה והזמן הנוכחי.
5. רק לאחר תשובת `2xx` עם `accepted: true` הציגי הצלחה. אפשר אז לפתוח את הודעת ה־WhatsApp הקיימת, ולהוסיף בסופה בשורה נפרדת את `whatsappReference` שהתקבל בתשובה. במקרה של שגיאה אל תפתחי WhatsApp ואל תציגי כאילו הפנייה נשמרה; הציגי אפשרות ניסיון חוזר עם אותו מזהה. חסמי לחיצות חוזרות בזמן השליחה.

שני המיקומים ישתמשו באותו `formId` ובאותה פונקציית שרת. כל לחיצה מפורשת יוצרת `submissionId` משלה; ניסיון חוזר של אותה לחיצה משתמש באותו מזהה. אין צורך בשני חיבורים. אין להכניס מפתח Supabase לדפדפן, ואין צורך לשנות את טופס WordPress: עמוד הקמפיין מציג כרגע iframe של Base44.

## בדיקת קצה מתואמת אחת, אחרי חיבור ואישור הפעלה

נבצע תרחיש בדיקה אחד עם **שתי פניות סינתטיות מובחנות**: אחת מהטופס בראש העמוד ואחת מהטופס בתחתיתו. לכל פנייה יהיה `submissionId` אחר ופרטים סינתטיים שונים. נוודא שנוצרה בדיוק רשומת `leads` אחת לכל פנייה — שתיים בסך הכול — עם שם, טלפון, נושא, מקור „דף נחיתה — יום גיבוש”, כתובת הדף וסטטוס „פתוח”. ננסה שוב את כל אחת מהן עם *אותו* `submissionId` שלה ונוודא שהמספר נשאר שתיים. אם נשלחת גם הודעת WhatsApp, נוודא שהעברת הבוט מפנה לרשומה המתאימה בלי ליצור ליד נוסף. לפני הבדיקה יש לוודא שהמספר שבקישור WhatsApp מחובר לבוט הרלוונטי. בדיקה זו לא בוצעה עדיין.
