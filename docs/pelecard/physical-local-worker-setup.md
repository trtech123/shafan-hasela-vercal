# Local physical worker setup (financial dispatch off)

Use the production Supabase project `shafan-hasela` (`divzxsynczeifkpnpupl`). This setup only checks the physical database and device assignment. The script hard-codes `PELECARD_PHYSICAL_DISPATCH_ENABLED=false`, so it cannot initiate J4.

1. In the Supabase dashboard, open the project and select **Connect**. Choose **Session pooler** (port 5432) for a local machine without IPv6. Copy the complete connection URI. Replace `[YOUR-PASSWORD]` locally with the database password from the approved secret store, percent-encoding reserved URL characters. Do not paste it into chat or save it in this repository. Do not reset the database password merely for this test; that could affect other production clients.
2. In **Project Settings → Database → SSL Configuration**, choose **Download Certificate**. Save the CA file outside the repository, for example under `%LOCALAPPDATA%\ShafanHasela\`. The certificate is public but the local worker reads its PEM content into `PELECARD_PHYSICAL_DATABASE_CA` and verifies the PostgreSQL server certificate.
3. Obtain the J4 user/password that Pelecard confirms for full terminal `2814926015`, register `004`. The existing digital secret names are not used by the physical worker. The physical user/password must be entered separately when prompted.
4. From this worktree's `app` directory, run `powershell -NoProfile -File scripts/configure-physical-worker-local.ps1 -CertificatePath "C:\path\to\downloaded-ca.crt"`. Enter the physical J4 username/password and complete database URL at the hidden prompts. Windows DPAPI stores the three values under `%LOCALAPPDATA%\ShafanHasela\physical-worker-secrets.xml`, outside Git; only the same Windows user on this machine can decrypt them.
5. Run `powershell -NoProfile -File scripts/physical-worker-local.ps1 -Mode check`. It reads the vault, CA file, and the existing general Supabase service-role key from the main workspace's ignored `app/.env.local`. It prints only the sanitized readiness result. Require `ready:true`, `register004:true`, `dispatchEnabled:false`.
6. For a no-charge running worker, use `-Mode run`. It still forces dispatch off. Stop with Ctrl+C. The process clears its physical secret environment variables on exit.

The scripts do not create an env file or modify digital Pelecard secrets. Never commit the encrypted vault, connection URI, or password. A production API deployment needs separately injected `PELECARD_PHYSICAL_TERMINAL`, `PELECARD_PHYSICAL_USER`, `PELECARD_PHYSICAL_PASSWORD`, `PELECARD_PHYSICAL_DATABASE_URL`, `PELECARD_PHYSICAL_DATABASE_CA`, `SUPABASE_URL`, `PELECARD_PHYSICAL_ENABLED`, and `PELECARD_PHYSICAL_DISPATCH_ENABLED`; the browser flag is `VITE_PELECARD_PHYSICAL_ENABLED`. Keep the financial dispatch flag false until a specific charge is authorized.
